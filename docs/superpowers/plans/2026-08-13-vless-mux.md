# VLESS Mux (v1.mux.cool) Client Implementation Plan (SP2)

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add the v1.mux.cool multiplexing client to xray-tui-native — a `MuxClient` opening one VLESS `command=0x03` tunnel to `v1.mux.cool:9527` and multiplexing concurrent TCP sessions, interoperable with xray/sing-box/mihomo VLESS inbounds.

**Architecture:** The mux tunnel is a VLESS byte stream (command 0x03) carrying self-delimiting mux frames `[2B meta_len][2B session_id][1B status][1B option][New: 1B network + port-first addr][2B data_len][payload]`. A demux task routes frames to per-session channels; each `SessionStream` reads its channel and writes 8KiB-chunked Keep frames. `connect_mux` mirrors `connect_udp`.

**Tech Stack:** tokio (AsyncRead/AsyncWrite, mpsc channels, Mutex), bytes, the existing engine TLS/REALITY + vision, rstest e2e vs xray 26.3.27 + sing-box 1.13.16.

**Spec:** `docs/superpowers/specs/2026-08-13-vless-mux-design.md` (wire authority: xray 26.3.27 `common/mux/{frame,writer,session,client,server}.go`).

## Global Constraints

- xray-tui-proto NEVER modified. No new dependencies. `NativeError`-only error surface.
- Wire (spec §4): frames `[2B meta_len][2B session_id BE][1B status][1B option][New: 1B network + port-first addr][2B data_len][payload]`; statuses 0x01 New / 0x02 Keep / 0x03 End / 0x04 KeepAlive; options 0x01 Data / 0x02 Error; addr port-first (atyp 0x01 IPv4 / 0x02 Domain / 0x03 IPv6); meta_len cap 512; 8 KiB chunking; dest `v1.mux.cool:9527`.
- Client semantics: first payload write status New, subsequent Keep, close → meta-only End, KeepAlive 0x04; session ids from 1.
- Deviations (spec §8): eager New frame on `open_session`; tunnel-level KeepAlive; distinct `connect_mux` entry; no mux config knobs.
- Clippy workspace pedantic+nursery 0; `cargo fmt --check` clean; every network step timeout-bounded.
- e2e: `native-e2e` + `XRAY_TUI_CORE_BIN_DIR=/tmp/core-bin`. Existing rows untouched (vless 61+4 → 65+4, vmess 48).

- [ ] **Step 3: Implement**

```rust
pub(crate) struct MuxClient<S> {
    tunnel: S,                       // consumed by the demux task
    next_id: AtomicU16,              // from 1
    sessions: Mutex<HashMap<u16, mpsc::Sender<SessionEvent>>>,
    write_tx: mpsc::Sender<Frame>,   // serialized writes through a writer task
    keepalive_tx: mpsc::Sender<()>,  // or a flag to stop the keepalive task
}
enum SessionEvent { Data(bytes::Bytes), End, Error(io::Error) }
```

- `new(tunnel)`: split the tunnel into read half (demux task) + write half (writer task). The **demux task** loops `read_frame`; routes `Data` payloads to the session's channel, `End` → send End, `Error` → send Error; unknown session_id → log + drop. On tunnel EOF/error → End all sessions. The **writer task** receives `Frame`s from `write_tx` and writes them sequentially (one write mutex via the channel). A **keepalive task** sends a KeepAlive frame every 10s (stops when the client drops).
- `open_session(target)`: `let id = next_id.fetch_add(1)`; create an mpsc channel; register in the sessions map; send an eager **New** frame (spec §8 deviation 1); return `SessionStream { rx, id, write_tx }`. On send failure (tunnel dead) → clean up + Err.
- `SessionStream` **read**: `rx.recv()` → Data → fill the read buffer; End → EOF; Error → io::Error. Cancellation-safe (buffered partial payloads).
- `SessionStream` **write**: chunk the app bytes at 8 KiB → for each chunk send a Keep frame (payload) via `write_tx`; on send failure → io::Error. `poll_flush` → ack (frames are write_all'd by the writer task; flush is a no-op unless a write is pending). `poll_shutdown` / Drop → send a meta-only **End** frame + unregister the session (fire-and-forget via write_tx).
- The write side must return the correct accepted-byte count (AsyncWrite contract: no Ok(0), buffer until the write_tx accepts the whole chunk).
